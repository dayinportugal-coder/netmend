In-browser converter vs Acrobat vs Excel

Three ordinary ways to get a table out of a PDF: export it from Adobe Acrobat, pull it into Excel with Get Data / Power Query, or run a converter in your browser. None of them is magic, and all three fail on a scan. This page says what each one is good at so you can pick on purpose.

The one thing they all need

A text layer. If you cannot highlight and copy an amount from the PDF, Acrobat’s table export, Excel’s “From PDF” and our in-browser tool will all struggle or return nothing useful. For scans, see scanned invoices — the work is typing, OCR plus ticking, or a done-for-you pass, not a different export button.

Adobe Acrobat (and similar paid PDF editors)

Acrobat can export a PDF to Excel, Word or a spreadsheet-like table, and it has OCR for scans if you pay for that feature. It is often the best of the three when the invoice is a designed layout: logos, two-column addresses, totals in a box on the right. It also keeps you inside a tool you may already have, and the export can be a real .xlsx.

The costs are money, and trust: the file is opened in a heavy desktop or cloud application, and a “Export to Excel” that is almost right is still wrong until you tick the totals. Acrobat does not know that a bank statement’s “balance brought forward” is not a transaction, or that an Amex front-page “new charges” total must not be imported twice. You still have to clean the sheet.

Excel Get Data / Power Query (From PDF)

Recent Microsoft Excel versions can load a PDF as a data source (Data → Get Data → From File → From PDF). When it works, it is excellent: you get a query you can refresh if next month’s statement has the same layout, you can filter out header rows, and you never leave Excel. Power Query is also honest about tables — it will often show you several detected tables (the summary block, the transactions, the footnotes) and let you pick.

The limits: you need a desktop Excel that includes that command (it is not in every edition, and it is not in Google Sheets). A slightly different statement layout next month can break the query. European versus US number formats still need a careful change type step, or 1.234 becomes 1.234 or 1234 in the wrong way. And the PDF has to sit where Excel can read it; this is a good choice for a bookkeeper who already lives in Excel, not for someone who just wants a CSV to upload to Xero tonight.

FAQ

Which method is the most accurate?

None of them, until you check the printed totals. A clean text PDF will usually come out well from all three. The differences show up on awkward layouts, and on whether you notice a dropped row.

Does the free tool replace Acrobat?

No. Acrobat is stronger on designed pages and offers OCR if you pay for it. The free tool is stronger on privacy, cost, and European versus US number formats for straightforward tables.

Can Google Sheets read a PDF the way Excel can?

Not with an equivalent “From PDF” query. Convert to CSV first, then import the CSV — and set the locale yourself.
