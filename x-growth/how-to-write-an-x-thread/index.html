Como escrever um thread no X

Um thread é uma boa forma quando tem uma sequência: um método, uma história com mais do que uma volta, ou uma lista que ficaria apertada numa só publicação. É uma má forma quando tem uma ideia e a está a esticar para parecer um «thread».

Se chegou aqui porque quer que um thread viaje longe, leia também a página companheira sobre escrever um chamado thread viral. O ofício é o mesmo. O limite honesto é o mesmo: pode tornar um thread fácil de ler, não pode ordenar que se espalhe.

As contas habituais continuam a trabalhar com um orçamento curto de caracteres por publicação; publicações mais longas existem em planos pagos do X. Veja o contador no seu próprio compositor. De uma forma ou de outra, uma ideia por publicação lê-se melhor no telemóvel do que uma parede de texto partida ao acaso.

Construa-o por esta ordem

  • Escreva o ponto numa frase. Se não conseguir, não está pronto para o pôr em thread.
  • Liste as publicações como títulos (cinco a oito no máximo, muitas vezes menos). Cada título é uma ideia.
  • Escreva a primeira publicação no fim. Tem de se aguentar sozinha no feed, com um gancho concreto.
  • Escreva o meio por ordem. Passos, exemplos, uma tentativa falhada, um limite. Numere se a sequência importar.
  • Escreva um fecho que seja uma conclusão ou um passo seguinte, não um suspense para uma «parte 2» que ainda não escreveu.
  • Corte. Leia uma vez sem piedade. Qualquer publicação que só diga «como referi» sai.

Threads e formas de exemplo

Thread de método, 5 publicações · exemplo
1/ Um projeto de freelancer que já não começo sem um briefing escrito. O briefing são quatro linhas.

2/ O que já existe: ficheiros, acessos, marca, rascunhos anteriores.

3/ Como é o «feito», em ficheiros entregáveis, não num sentimento.

4/ A data limite, e porque é essa data.

5/ Quem aprova — um nome. Se essas quatro linhas não puderem ser escritas, não marcamos uma chamada de arranque. É o método todo.
Thread de história, 4 publicações · exemplo
1/ Tivemos um pedido a que respondemos 40 vezes em outubro, e não era um erro.

2/ As pessoas colavam um token de API no campo do ID do espaço de trabalho. A documentação dizia para não o fazer. A documentação não estava a ser lida naquele momento.

3/ Mudámos o nome do campo, pusemos um valor de exemplo na caixa, e passámos a rejeitar tokens com um erro específico.

4/ Os pedidos desceram. A lição que fiquei: se um erro se repete, mude a interface, não só o artigo de ajuda.
Thread de lista, 4 publicações · exemplo
1/ Quatro coisas que ponho numa ficha de produto antes de qualquer adjectivo.

2/ De que é feito, e um limite do material (esta camisola encolhe na máquina de secar).

3/ Quando sai, em datas que consigo cumprir, não «o mais rápido possível».

4/ Como funciona uma devolução, nas mesmas palavras da política oficial. Os adjectivos podem vir depois destas quatro, ou não vir.
Quando não fazer thread · exemplo
Se a segunda publicação é só um remate, tem uma publicação única.
Se está a repetir a mesma ideia com palavras novas, tem uma publicação única.
Se a parte útil é um link, escreva uma publicação e o link, não uma pista de publicações vazias.
Primeira publicação, fraca e mais forte · exemplo
Fraca: «Umas ideias sobre briefings, um thread.»

Mais forte: «Já não começo um projeto de freelancer sem um briefing de quatro linhas. Aqui estão as quatro linhas, e o que faço se não puderem ser escritas.»
Numeração · exemplo
Numerar ajuda quando a ordem importa (um método, uma linha de tempo). É opcional quando está a oferecer um conjunto de exemplos. Se numerar, mantenha a contagem honesta: não escreva «1/17» e fique sem matéria no 6.
Um fecho · exemplo
Útil: «É o método todo. Uso-o em projetos de sites; o seu ofício pode precisar de outras linhas.»

Menos útil: «Siga-me para a parte 2, onde revelo o modelo.» Se o modelo é o ponto, pertence a este thread, ou a uma página ligada.
Passagem de edição · exemplo
Leia só a publicação 1. Abriria o resto?
Leia só a última. Fecha, ou esmorece?
Leia o meio na pré-visualização do telemóvel. Corte uma publicação. Se nada partir, deixe-a cortada.

Estes são rascunhos originais, escritos para esta página, de um profissional fictício. Não são publicações de uma conta real, nem uma promessa de alcance, clientes ou vendas. Adapte a estrutura e substitua cada facto por um que consiga defender.

Se quiser 10 rascunhos de threads curtos no seu tom, escolha «threads curtos» no X Post Writer grátis, cole algumas publicações antigas e o índice, e depois corte. A ferramenta inventa com gosto um sexto passo que não usa. Retire-o.

Perguntas frequentes

Publicação única ou thread?

Se um ecrã consegue conter a ideia sem a apertar, use uma publicação única. Os threads custam um clique ao leitor. Gaste esse clique só quando a sequência precisar dele.

Posso acrescentar imagens a cada publicação?

Sim, se cada imagem ganhar o lugar (um diagrama, uma captura que tenha autorização para mostrar). Imagens decorativas em cada publicação atrasam as pessoas.

Devo fixar um thread?

Fixe um que ainda descreva o trabalho que faz. Uma discussão datada ou uma promoção de uma semana é uma má fixação.
